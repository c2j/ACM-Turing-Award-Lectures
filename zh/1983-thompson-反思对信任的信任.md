# 反思对信任的信任

**Reflections on Trusting Trust**

> 肯·汤普森(Ken Thompson)
> 1983 年 ACM 图灵奖演讲
> 原载 *Communications of the ACM*, Vol. 27, No. 8 (1984 年 8 月), pp. 761–763
> 译自 ACM DL 扫描件 `1283920.1283940.pdf`(个人学习用途)

> 我们应在多大程度上相信"某个程序没有特洛伊木马"这样的断言?也许,更重要的是信任编写这个软件的人。

## 引言

感谢 ACM 授予我这个奖项。我不禁觉得,我获此殊荣,时机与机缘的成分不亚于技术上的功绩。UNIX¹ 随着整个行业从中央大型机向自主小型机的转变而风行一时。我猜想,如果 Daniel Bobrow [1] 当年买不起 PDP-10、不得不"屈就"一台 PDP-11 的话,今天站在这里的就会是他而不是我〔译注3〕。况且,UNIX 的今天是一大批人共同劳动的结果。

有句老话说:"和带你来的人跳舞"(Dance with the one that brought you)〔译注4〕,意思是我理应谈谈 UNIX。但我已经多年没有参与 UNIX 主线的工作了,却仍在不断地因他人的工作而获得我不配得到的赞誉。所以,我不打算谈 UNIX——但我要感谢每一位做出过贡献的人。

这就说到了 Dennis Ritchie〔译注5〕。我们的合作堪称一件美妙的事。在共事的十年里,我只记得一次工作上的失调:那一次,我发现我们俩各自写了同一个 20 行的汇编程序。我比对了两份源代码,惊讶地发现它们逐字符完全一致。我们合作的成果,远远大于我们各自贡献之和。

我是一名程序员。在我的 1040 报税表〔译注6〕上,职业一栏填的就是这个。作为程序员,我写程序。下面我想向各位展示我写过的最"可爱"的程序。我将分三个阶段来讲,并在最后把它们串起来。

## 第一阶段

上大学时——那还是电子游戏出现之前——我们靠互相出编程题来消遣。其中最受欢迎的一道题是:写出最短的自复制程序〔译注7〕。既然这是一个脱离实际的练习,通常的载体自然是 FORTRAN。实际上,选 FORTRAN 的理由,和两人三足赛跑之所以流行是同一个理由〔译注8〕。

更精确地说,问题是:写一个源程序,使它在编译并执行后,输出的恰好是它自己源代码的一份精确副本。如果你从未做过这道题,我强烈建议你自己试一试。自己发现解法所带来的启示,远胜过别人直接告诉你答案。"最短"只是为了比拼技巧、决出胜者而设的激励。

图 1 展示了一个用 C 语言 [2] 写的自复制程序。(较真的人会指出:这个程序并不严格是一个自复制程序,而是会*产出*一个自复制程序。)这份答卷太长,拿不了奖,但它演示了这一技术,并且具有两条对我后面的故事至关重要的性质:1)这个程序可以很容易地由另一个程序生成;2)这个程序可以携带任意数量的"多余行李",它们会与主算法一起被复制。在这个例子里,连注释也被复制了。

```c
char	s[] = {
	'\t',
	'0',
	'\n',
	'}',
	';',
	'\n',
	'\n',
	'/',
	'*',
	'\n',
	(此处删去 213 行)
	0
};

/*
 * 字符串 s 是本程序
 * 从 '0' 到末尾的
 * 程序体的一个表示。
 */

main()
{
	int i;

	printf("char\ts[] = {\n");
	for(i=0; s[i]; i++)
		printf("\t%d,\n", s[i]);
	printf("%s", s);
}
```

为了让不懂 C 的读者也能读懂这段代码,这里给出几条简单的对照:

| 记号 | 含义 |
|---|---|
| `=` | 赋值 |
| `==` | 等于(.EQ.) |
| `!=` | 不等于(.NE.) |
| `++` | 自增 |
| `'x'` | 单字符常量 |
| `"xxx"` | 多字符字符串 |
| `%d` | 转换为十进制的格式 |
| `%s` | 转换为字符串的格式 |
| `\t` | 制表符 |
| `\n` | 换行符 |

## 第二阶段

C 编译器是用 C 写的。我接下来要描述的,是编译器用自身语言编写时会出现的诸多"先有鸡还是先有蛋"问题之一。这里我用 C 编译器中的一个具体例子来说明。

C 允许用字符串结构来指定一个初始化的字符数组。字符串中的单个字符可以用转义方式表示不可打印字符。例如,

```
"Hello world\n"
```

表示一个字符串,其中的"\n"代表换行符。

图 2.1 是 C 编译器中解释字符转义序列那段代码的理想化版本。这是一段令人惊叹的代码。它以完全可移植的方式"知道"任何字符集中换行符应编译成什么字符码。这份"知道",使它能够重新编译自身,从而让这份知识代代相传。

```c
	...
	c = next();
	if(c != '\\')
		return(c);
	c = next();
	if(c == '\\')
		return('\\');
	if(c == 'n')
		return('\n');
	...
```

**图 2.1**

假设我们想扩展 C 编译器,加入序列"\v"来表示纵向制表符。对图 2.1 的扩展是显而易见的,见图 2.2。然后我们重新编译 C 编译器——却得到一个诊断错误。显然,由于编译器的二进制版本还不认识"\v",这份源代码还不是合法的 C。我们必须先"训练"编译器。等它"知道"了"\v"是什么意思之后,我们的新写法才会成为合法的 C。我们查 ASCII 表得知纵向制表符是十进制 11,于是把源代码改成图 2.3 的样子。现在,旧编译器接受了新源代码。我们把编译出的二进制安装为新的官方 C 编译器,这之后就可以按图 2.2 那种可移植的写法来写了。

```c
	...
	c = next();
	if(c != '\\')
		return(c);
	c = next();
	if(c == '\\')
		return('\\');
	if(c == 'n')
		return('\n');
	if(c == 'v')
		return('\v');
	...
```

**图 2.2**

```c
	...
	c = next();
	if(c != '\\')
		return(c);
	c = next();
	if(c == '\\')
		return('\\');
	if(c == 'n')
		return('\n');
	if(c == 'v')
		return(11);
	...
```

**图 2.3**

这是一个深刻的概念。它是我见过的最接近"会学习"的程序:你只需告诉它一次,之后就可以使用这个自指的定义了。

## 第三阶段

再回到 C 编译器。图 3.1 表示 C 编译器的高层控制流,其中例程"compile"被调用来编译下一行源代码。图 3.2 展示了对编译器的一个简单修改:每当匹配到某个特定模式时,它就故意错误地编译源代码。如果这不是故意的,它会被称为编译器"bug";既然是故意的,就应该称之为"特洛伊木马"。

```c
compile(s)
char *s;
{
	...
}
```

**图 3.1**

```c
compile(s)
char *s;
{
	if(match(s, "pattern")) {
		compile("bug");
		return;
	}
	...
}
```

**图 3.2**

我实际植入编译器的那个 bug,会匹配 UNIX"login"命令中的代码。替换代码会错误地编译 login 命令,使它既接受正确的加密口令,也接受一个特定的已知口令。这样,只要这段代码被装进二进制、且该二进制被用来编译 login 命令,我就能以任何用户的身份登录那个系统。

如此明目张胆的代码不会长期不被发现。哪怕最随意地翻阅一下 C 编译器的源代码,也会引起怀疑。

最后一步见图 3.3:在已有的木马之外再加入第二个特洛伊木马。第二个模式瞄准的是 C 编译器本身,其替换代码是一个第一阶段那样的自复制程序,它会把*两个*木马都插入编译器。这需要一个如第二阶段例子中的"学习"环节:我们先用正常的 C 编译器编译这份修改过的源代码,得到一个带 bug 的二进制,并把它安装为官方 C 编译器。之后,我们就可以把这些 bug 从编译器源代码中删掉——新的二进制会在每次编译编译器时自动把 bug 重新插入。当然,login 命令也将一直带着 bug,而任何源代码中都找不到丝毫痕迹。

```c
compile(s)
char *s;
{
	if(match(s, "pattern1")) {
		compile("bug1");
		return;
	}
	if(match(s, "pattern2")) {
		compile("bug2");
		return;
	}
	...
}
```

**图 3.3**

## 寓意

寓意是显而易见的:你不能信任那些不是完全由你自己创造的代码(尤其是来自雇用了像我这种人的公司的代码)。再多的源代码级验证与审查,也无法保护你免受不可信代码的侵害。在演示这类攻击的可能性时,我挑的是 C 编译器;我同样可以挑任何处理程序的程序,比如汇编器、加载器,甚至硬件微码。程序所处的层次越低,这类 bug 就越难被发现。一个安装得当的微码 bug 几乎不可能被检测出来。

在努力让各位相信我不可信之后,我还想说几句道德层面的话。我想批评新闻界对"黑客"——414 帮、Dalton 帮之类〔译注12〕——的报道方式。这些孩子的行为往轻了说是故意破坏,往重了说很可能构成非法侵入与盗窃。使这些黑客免于严厉起诉的,仅仅是刑法的不完备。易受此类活动侵害的公司(而大多数大公司都非常脆弱)正在大力推动刑法的更新。未经授权访问计算机系统在少数几个州已属重罪,更多州的立法机构以及国会也正在处理这一问题。

一个爆炸性的局面正在酝酿。一方面,报刊、电视和电影把这些搞破坏的人捧为英雄,称他们是"神童"(whiz kids);另一方面,这些孩子的行为很快将会招致数年监禁。

我看过这些孩子在国会作证。很明显,他们完全没有意识到自己行为的严重性。这显然是一种文化断层。闯入计算机系统这一行为,必须背负与闯入邻居家宅相同的社会污名——邻居家的门没上锁不应成为理由。新闻界必须明白:对计算机的滥用,并不比酒后驾车更值得惊叹。

**致谢**。我最早是在美国空军对早期 Multics 实现的一份安全评审 [4] 中读到这种特洛伊木马的可能性的。我找不到该文档更具体的出处,如有人能提供这一文献信息,我将不胜感激〔译注13〕。

## 译注

**文本与翻译说明**

1. ¹ 原文脚注:UNIX 是 AT&T 贝尔实验室的商标。
2. 标题 *Reflections on Trusting Trust* 亦有译作《对信任的信任》《信任信任之反思》等。文中 Thompson 描述的攻击后被称为"Thompson 攻击"或"信任信任攻击"(trusting trust attack)。

**背景与文化注**(译者补注,原文无)

3. 〔译注3〕 Daniel Bobrow,人工智能学者,时任职于 BBN 公司,参考文献 [1] 即其参与研制的 PDP-10 分时系统 TENEX。PDP-10 是昂贵的大型分时主机,PDP-11 则是便宜得多的小型机。此处是 Thompson 的自嘲:UNIX 的风行,很大程度上是因为它恰好运行在廉价小型机上,赶上了行业从大型机转向小型机的浪潮——这正呼应上文"时机与机缘的成分不亚于技术上的功绩"。
4. 〔译注4〕 "Dance with the one that brought you" 是美国俗谚,源于舞会礼仪:谁带你来舞会,你就应当同谁跳舞。引申为"不可忘本,应忠于成就你的人或事物"。Thompson 因 UNIX 获奖,按此理"理应谈谈 UNIX"。
5. 〔译注5〕 Dennis Ritchie,C 语言设计者、UNIX 共同创造者,与 Thompson 同获 1983 年图灵奖。其获奖演讲《软件研究之反思》(*Reflections on Software Research*)与本文发表于同期 CACM,两篇标题亦相互呼应。
6. 〔译注6〕 1040 表(Form 1040)是美国联邦个人所得税申报表,上有"职业"(occupation)一栏。此处意在强调:即便功成名就,他对自己的身份认定始终是"程序员"。
7. 〔译注7〕 "自复制程序"(self-reproducing program)后来通称 quine(奎因程序),得名于哲学家 W. V. O. Quine,因其研究过语句自指问题。
8. 〔译注8〕 原文 "three-legged race" 即"两人三足"赛跑(两人相邻的腿绑在一起跑步的游戏)。言下之意:用 FORTRAN 写自复制程序,其乐趣恰恰来自工具的笨拙滑稽——正如两人三足赛跑的乐趣来自跑不快。

**印刷与 OCR 勘误**

9. **原刊图题勘误**:CACM 1984 年 8 月号原刊第 762 页上,图 2.1 与图 2.2 的图题印反了(基础版代码框下印的是"FIGURE 2.2",含 `\v` 扩展的代码框下印的是"FIGURE 2.1",与正文叙述矛盾)。本译文按正文逻辑顺序排列:图 2.1 为基础版,图 2.2 加入 `'v'` → `'\v'`,图 2.3 将其改为 `return(11)`。
10. 图 1 中"(此处删去 213 行)"为原文排版所加,表示字符数组 `s` 的完整内容(即程序体每个字符的数值)在刊印时被省略。
11. 扫描件 OCR 中所有转义字符均已损坏(如 `\n` 被识别为 `kn`),本译文代码均对照原刊页面图像逐行校正。

**时代背景**(译者补注,原文无)

12. 〔译注12〕 "414 帮"(the 414s)指 1983 年入侵洛斯阿拉莫斯国家实验室、斯隆-凯特琳癌症中心等数十家机构计算机系统的密尔沃基青少年黑客团体,以当地电话区号 414 得名,案发后成员曾赴国会作证——即下文"我看过这些孩子在国会作证"所指。"Dalton 帮"指纽约私立 Dalton 学校学生入侵计算机网络的事件;媒体如此称呼亦是双关——Dalton Gang 本是 19 世纪美国西部著名的劫匪团伙。同年电影《战争游戏》(*WarGames*)热映,正是这波媒体将少年黑客浪漫化为"神童"(whiz kids)风潮的写照,也是 Thompson 此处批评的对象。
13. 〔译注13〕 Thompson 寻找的这份文献,后来被确认为 Karger 与 Schell 1974 年的 Multics 安全评估报告:Karger, P.A., and Schell, R.R. *Multics Security Evaluation: Vulnerability Analysis*, ESD-TR-74-193, Vol. II, 美国空军电子系统部,1974 年 6 月。该报告首次提出了在编译器中植入自我延续后门的设想。
