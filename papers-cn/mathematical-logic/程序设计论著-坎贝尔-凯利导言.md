# 程序设计论著——坎贝尔-凯利导言

**Turing's Papers on Programming: Preface (by Martin Campbell-Kelly)**

> 责任者:马丁·坎贝尔-凯利(Martin Campbell-Kelly)
> 原载 *Collected Works of A.M. Turing: MATHEMATICAL LOGIC*,Elsevier,2001,印刷页 243–250(PDF 页 256–263)
> 译自 `papers/Mathematical Logic-Elsevier (2001).pdf`(个人学习用途)

除早年涉足程序验证的《核查一个大例行程序》("Checking a Large Routine")[Turing 1949] 之外,图灵的程序设计论著在思想层面是令人失望的。1948 年 9 月,他出任曼彻斯特大学计算机实验室副主任(Assistant Director),学衔为 reader〔译注1〕。他的明确职守是让曼彻斯特计算机面向广泛的人群开放使用,并为此提供必要的程序设计基础设施。然而对用户们来说不幸的是,图灵对为自己的研究编写程序的兴趣,远远大于开发程序设计系统、让计算机更便于他人使用。

在加入曼彻斯特大学之前,1946–47 年间图灵曾在国家物理实验室与 J.M. 威尔金森(J.M. Wilkinson)共事,研究 ACE 的编码问题。不过那纯属为一台尚不存在的机器"纸上编程" [Wilkinson 1948]。到了曼彻斯特,图灵才第一次获得为真实计算机编程的经验,而且他是当时刚投入运行的原型机的头号重度用户。在"能用于完整规模问题的寥寥时间里"〔译注2〕,图灵主要的程序设计成果包括梅森数的素性检验,以及一项围绕黎曼假设的计算研究——后者载于其论文《黎曼 ζ 函数的一些计算》(Turing 1953;1951a,pp. 96–97)。

由本地电气工程企业弗兰蒂公司(Ferranti)承制的曼彻斯特计算机全面工程化版本,于 1951 年 2 月安装进曼彻斯特大学计算机实验室——见图 1。(该机以 Ferranti Mark I 之名销售,但在当地却——令人困惑地——称作"曼彻斯特电子计算机 Mark II";后来干脆简称 Mark I。〔译注3〕)

图灵为这台机器撰写了程序员手册,约于 1951 年 3 月印行。手册约一百页对开幅面打字稿,包含 Mark I 指令码的大量艰深细节——这套指令码与图灵关系甚微——因此没有收入《全集》。不过手册里有一节引人入胜的文字,《程序设计原理》,那是纯粹的图灵手笔,本卷在此重印。这份节选满是图灵在同原型机搏斗中学到的实用编程心得:他讲述了子例程的用法,框图(他称之为"方框示意图")的用法,还有"核对表"(check sheets)——把程序的预期行为与其真实执行相对照,用作排错的辅助。他解释了后来所谓"空间—时间折衷"的道理,并描述了后来冠名"逐步求精"与"自底向上编码"等的程序分解技术。这些材料固然有趣,却无论如何算不上对程序设计这门学问的重要贡献;毋宁说,它们正是二十世纪五十年代初英美众多早期计算机实验室各自独立摸索出来的编程实践的一个典型标本。

图灵为 Mark I 所做的工作中,最不能令人满意的方面,是他强加给机器用户的编程记法。图 2 是图灵 INPUT 例程的影印件,该例程用于把程序自穿孔纸带读入机器——相当于后来所谓汇编程序的一种原始形态。要想读懂这段代码,唯有对整本程序员手册下一番苦功方有可能,即便如此也绝非直截了当。此处照录它,基本上是当作一件"证物"(exhibit)——它让我们看到图灵的程序"长相如何"。每条程序指令由 20 个二进制位组成,图灵将其写作四个字符,所用者为 5 位邮局电传打字机码。实际上,他是把电传码当成一套三十二进制数系来用的,其"数字"为:

```
/E @A:SIU 1DRJNFCKTZLWHYPQOB G"MXVs
```

〔译注4〕

雪上加霜的是,数是反着写的,符号落在最右端(这正是 Mark I 这类串行机上数呈现的方向)。由于零以斜杠"/"字符表示,而这个字符又是程序与数据书写形态中最常用的字符,一位早期用户断定,这必定是对曼彻斯特出了名的阴郁天气的无意识反映——纸面上的效果,恰似隔着一扇脏玻璃窗看雨!图灵提供的程序纸从不附带任何解释编码的批注,用户要么照单全收,要么费尽气力自行破译。〔译注5〕

图灵似乎对自家记法要求普通用户做何种脑力体操浑然不觉。莫里斯·威尔克斯(Maurice Wilkes)为剑桥同时代的 EDSAC 开发了一套干净得多、对用户友善得多的记法,他后来评说道,这套记法"怪诞之至",并进一步补充说,图灵"本人脑子极其敏捷,便觉得没有必要向天赋不及者让步"(Campbell-Kelly 1980)。于是,剑桥计算机用户写 A 250 L 就表示"把 250 号存储单元里的长数加进累加器"之类的指令,而曼彻斯特的程序员却不得不写出 GUTC 这类东西来。(这里加法操作码记作 TC,而地址 250 按三十二进制倒写为 GU。〔译注6〕)

图灵关于 Mark I 编程技术唯一正式发表的论文《局部程序设计方法与惯例》("Local Programming Methods and Conventions"),于 1951 年 7 月在曼彻斯特大学计算机落成典礼会议上宣读(AMT 1951b)——见图 3。

这篇论文内容相当浅白,试图为指令与数字双双采用那套拗口的三十二进制记法辩护,却难得成功。例如他评论道:"既然存储单元的名字不过是随意的标签,用什么代码来称呼它们无关紧要。"恐怕唯有图灵本人,才会相信 GU 和 250 同样配作一个存储单元的好名字。

不过,替图灵的程序设计系统说句公道话,应当指出:尽管记法别扭,他营造的环境却是有章有法、井井有条的。库例子例程按标准方式检验并编制文档,图灵还为机器的使用设计了系统化的操作规程。这份对实务的用心,很可能是他从布莱切利园战时经历承袭而来的一份文化遗产。最后,图灵的编程记法还带来了一项始料未及的好处:用户们被它折腾得叫苦不迭,曼彻斯特大学遂迅速走在了开发自动编码系统、以免手工编码之苦的前列。其他那些坐拥较友好记法的计算机实验室,反倒花了长得多的时间才迈出这一步。

### 背景与文化注

1. 〔译注1〕**reader 与实验室建制**:reader 为英国大学介于高级讲师与教授之间的学衔,约合北美副教授。"计算机实验室"(Computing Machine Laboratory)为曼彻斯特大学专设机构,负责弗兰蒂工程版机器的日常运转与对外服务;"副主任"之下另有主管工程师。图灵的实际角色更近于首席用户兼顾问,而非服务提供者——这正是下文抱怨的由来。
2. 〔译注2〕**原型机岁月**:1948–49 年曼彻斯特"婴儿机"放大版(Prototype Mark I)调试期间,机器时间绝大部分被硬件验收占用,用户(含图灵)只能在深夜与周末挤用机时;图灵用它做了 Mersenne 数素性检验(找大素数)与黎曼 ζ 函数零点计算(检验黎曼假设,即著名的 TITCH-WELL 批任务)。
3. 〔译注3〕**Mark I / Mark II 名实之辨**:大学校内沿袭原型机序列称工程版为 "Manchester Electronic Computer Mark II",而弗兰蒂公司商品名为 "Ferranti Mark I";今人通称后者,故本篇标题仍作 "Turing's Papers on Programming"(指曼彻斯特时期论著)。
4. 〔译注4〕**电传码即三十二进制**:5 位电传打字机码(ITA2,博多码系)恰有 32 个码位,图灵径取其打印字形充当 0–31 的"数字",20 位指令即四个"数字"。表中首字符"/"即数值 0(零),末位对应 31。此表 OCR 可信度低,详见勘误节。
5. 〔译注5〕**斯特雷奇**:Christopher Strachey(1916–1975),当时为中学教师兼哈韦尔实验室访问研究员,1951 年借曼彻斯特机写出跳棋程序与合信—爱恋信生成程序,后为程序设计语言理论奠基人(CPL 语言、指称语义先驱)。他在图灵 INPUT 例程纸上的批注,是研究早期编程实践的珍贵实物。曼彻斯特阴雨之谑出自坎贝尔-凯利访谈记录,当事人未具名。
6. 〔译注6〕**GU TC 与 A 250 L**:EDSAC 助记记法中 A 为"加"、250 为地址、L 表示长(69 位)操作数,近乎自明;Mark I 中同一加法须拆作函数码 TC 加倒写三十二进制地址 GU(= 7×32+30 = 254?按倒序读出为 250),非经手册训练不可解。威尔克斯与图灵同为 1967 年前后计算机界元老,两人记法之争是早期"可用性"问题的著名公案;引文出处 Campbell-Kelly 1980(见文末文献表)。
7. 〔译注7〕**自动编码系统**:指 1954 年起布罗克(R. A. Brooker)等在曼彻斯特开发的 Mark I 自动机(Autocode)——英国最早的实用高级编程系统之一。坎贝尔-凯利的论点:记法之恶反而催生了自动化之善;剑桥 EDSAC 记法顺手,故子程序库发达而自动编码迟至数年后。
